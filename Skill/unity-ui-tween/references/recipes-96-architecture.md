# 96 条场景配方展馆

新馆以原方案的 12 层级、96 条场景为主目录。每条记录操作对象、状态迁移、素材、推荐参数、边界与减弱动态表达。旧 46 项、后续扩展及旧场景保留归档；主导航不使用这些旧编号。

## 页面与交互

默认画面遵循用户指定的“卡牌与拖放”原图，提供卡牌/拖放/基础动画快捷入口。左下“全部配方 / 搜索”展开原方案的 12 层级、96 条完整目录，以及名称、状态、素材查询和可叠加筛选。快捷入口不是额外计入 96 条的新配方。目录自动滚动到所选配方。

卡牌与拖放在同一大舞台直接操作，其余配方保留两句操作/观察提示。顶部和右侧按钮控制播放与重置；舞台底部“时间轴”展开重播、暂停/继续、0.25× 慢放和采样工具。检查器齿轮打开验收说明、减弱动态开关和 JSON 导出。拖拽场景显示实际频率/阻尼参数，固定时长场景使用 Tween 参数。

框架使用定稿的金属灰/蓝灰面板；高饱和游戏图形集中在舞台对象。舞台模拟操作按钮属于工具控制，保持中性色。场景内的真实按钮使用拆分后的游戏美术。

## 代码边界

- `Runtime/RecipeCatalog.cs` 加载并校验 01.01–12.08。目录数据不包含场景实例引用。
- `Gallery/RecipeGalleryBootstrap.cs` 管理展馆、筛选、参数与 schemaVersion=4 配置导出。
- `Gallery/RecipeStage.*.cs` 是宿主场景示例：状态与操作决定结果，纯表现闭包绘制动画。输入、列表、拖放、任务、奖励均使用实际示例数据。
- `Runtime/MotionChannelArbiter.cs` 提供对象与属性的原子租约。同一对象的不同属性可以分别持有；冲突时先静默取消旧持有者。新场景采用单一协调器，为全部绑定视觉对象申请通道，包含 secondary 和子项；不是允许任意多个场景控制器自动混写属性。
- `Gallery/RecipeArt.cs` 从原始 imagegen 图集与 manifest 创建缓存 Sprite。没有运行时抠图、重绘或图像占位替换。

`RecipeStage` 是可阅读和复用的完整场景示例，不是对任意宿主自动推断业务的黑盒组件。接入游戏时替换示例数据与操作入口，保留宿主的奖励持久化、导航、请求与列表身份系统。`01.01` 等新编号不可传给旧 `MotionPlayer.Play`。

## 表现与时间

业务变更发生在操作处理器内。Seek、Replay 和视觉求值不发奖、不删除数据、不重新执行点击。重播只重看最近一次已确定的迁移，重置才恢复初始数据。每个场景只有一个固定时长协调器；新请求停止旧 Tween，从当前显示姿态捕获新的起点。循环只有一个实例，隐藏与销毁停止更新。

固定时长效果支持暂停、慢放、定位与继续；所有 Tween 使用 unscaled 时间。未发生可采样迁移时，时间轴禁用。拖拽直接跟手并使用解析弹簧回位，不伪装成可倒拖的预制时间轴。原生 ScrollRect 拥有惯性与边界弹性；手动输入打断滚动跳转。倒计时按真实截止时间计算，不因暂停表现而暂停业务时间。真实任务完成数控制已知进度，加载图形不反推任务结果。

## 构建与验证

使用 Unity 6000.0.26f1、UGUI 2.0.0 和仓库原有 DOTween 免费版。执行 `scripts/recipes96.ps1 -Target Build` 构建新馆，`-Target Validate` 在可见 Player 窗口验证两个桌面尺寸。旧构建目录和 Gallery.unity 不重建、不删除。新馆为默认构建场景，提供旧馆归档入口。

测试报告与每项截图在 `docs/validation/`、`docs/previews/v070/cases/`。脚本化输入和截图检查不等同于第二台电脑、移动真机或真人可用性验收；各阶段见独立验收矩阵。
